


## Verilog explanation by Gemini

ZynqなどのFPGAでLチカ（LED点滅）に挑戦されているのですね！このコードは、ただ点滅させるだけでなく、**一定時間ごとにLEDの色を切り替える**（RGB LEDを想定）という少し応用的な内容になっています。

Verilogの基本ルールに触れながら、上から順に解説します。

---

### 1. モジュールの定義と入出力
```verilog
module blink (
    input    CLK,
    input    RST,
    output reg [2:0]   LED_RGB
);
```
*   **`module` ~ `endmodule`**: Verilogの基本単位です。1つのファイルに1つの部品（モジュール）を作るイメージです。
*   **`input / output`**: チップのピンを定義します。`CLK`はクロック信号、`RST`はリセットボタンです。
*   **`reg [2:0]`**: 3ビット幅の信号で、値を保持できる（レジスタ）タイプであることを示します。RGBの3色分ですね。

---

### 2. 内部レジスタ（カウンタ）の宣言
```verilog
reg [25:0] cnt26;
```
*   **`[25:0]`**: 26ビット幅の変数です。なぜこんなに大きいかというと、FPGAのクロック（100MHzなど）は非常に速いため、人間が見える速度まで落とすには、大きな数まで数える必要があるからです。

---

### 3. メインカウンタの動作（alwaysブロック）

```verilog
always @( posedge CLK ) begin
    if (RST)
        cnt26 <= 26'h0;
    else
        cnt26 <= cnt26 + 1'h1;
end
```
*   **`always @(posedge CLK)`**: 「クロックが立ち上がった（0から1になった）瞬間だけ動く」という宣言です。
*   **`<=` (非ブロッキング代入)**: 順序回路で使われる「一斉に値を更新する」書き方です。
*   **`26'h0`**: `<bit_length>'<p-adic><value>`: 「26ビットの、16進数(h)で、0」という意味です。
    * `h`: Hexadecimal
    * `d`: Decimal
    * `b`: Binary
*   **動作**: クロックごとに `cnt26` を 1 ずつカウントアップし、リセットが押されたら 0 に戻します。

---

### 4. 条件フラグの作成（文法ミス修正あり）
```verilog
wire ledcnten = (cnt26 == 26'h3ffffff);
```
*   **修正点**: おそらく `write` ではなく `wire` です。
*   **`wire`**: 配線（組み合わせ回路）を定義します。
*   **動作**: `cnt26` が最大値（26進数でFが並ぶ値）になった瞬間だけ、この `ledcnten` 信号が **1（True）** になります。これが次のカウンタを動かす「トリガー」になります。

---

### 5. LEDの状態管理用カウンタ
```verilog
reg [2:0] cnt3;

always @(posedge CLK) begin
    if (RST)
        cnt3 <= 3'h0;
    else if (ledcnten)
        if (cnt3 == 3'd4)
            cnt3 <= 3'h0;
        else
            cnt3 <= cnt3 + 3'h1;
end
```
*   **`if (ledcnten)`**: 普段は何もしませんが、さきほどのメインカウンタがいっぱいになった瞬間（約0.6秒〜1秒周期程度）だけ、中身を実行します。
*   **動作**: 0 → 1 → 2 → 3 → 4 と数え、4になったら0に戻る「5段階カウンタ」です。

---

### 6. LEDの色の決定（デコーダ）
```verilog
always @* begin
    case (cnt3)
        3'd0:    LED_RGB = 3'b100; // 赤
        3'd1:    LED_RGB = 3'b010; // 緑
        3'd2:    LED_RGB = 3'b001; // 青
        3'd3:    LED_RGB = 3'b111; // 白（全部点灯）
        3'd4:    LED_RGB = 3'b000; // 消灯
        default: LED_RGB = 3'b000;
    endcase
end
```
*   **`always @*`**: 中身の信号が変わった瞬間にいつでも計算する「組み合わせ回路」です。
*   **`case` 文**: `cnt3` の値に応じて、`LED_RGB` の出力を決めます。
*   **`3'b100`**: 「3ビットの、2進数(b)で、100」という意味です。左からR, G, Bに対応していることがわかります。

---

### まとめ：このコードは何をしている？

1.  **高速なクロック**を26ビットカウンタで数えて、ゆっくりなタイミング（`ledcnten`）を作ります。
2.  そのタイミングで **0~4までのモード**を切り替えます。
3.  モードに合わせて、**LEDの色を 赤→緑→青→白→消灯 とループ**させています。

Zynqで動かす際は、`CLK` や `LED_RGB` がどのピンに繋がっているかを指定する「制約ファイル（.xdc）」も必要になりますので、そちらもセットで確認してみてくださいね。


---

Verilog特有の書き方は、プログラミング言語（C言語など）の常識で考えると少し混乱しますよね。
一つずつ、FPGAという「ハードウェア」を設計する視点で紐解いていきましょう。

---

### 1. 予約語と宣言について
*   **予約語ですか？**: 
    `input`, `output`, `reg`, `module`, `always`, `if`, `else`, `case` などは**予約語**です。
    一方で、`CLK` や `RST` は人間が勝手に決めた**信号名（変数名のようなもの）**です。
*   **暗黙の宣言について**: 
    Verilogでは変数の宣言は必須です。`h0` や `h1` という変数が暗黙に作られることはありません。これらは「値」そのものを表しています（後述します）。

---

### 2. `reg` とレジスタ（メモリ）
*   **レジスタとは？**: 
    CPUの中にあるレジスタと同じで、**「1クロックの間、値を保持しておく箱」**のことです。
    メモリ（RAM）というよりは、回路上の「フリップフロップ（FF）」という最小単位の記憶素子を指します。
*   **`reg [25:0] cnt26`**: 
    はい、その通りです。`cnt26` という名前の箱があり、それが26個のビット（0番〜25番）を並べた「26ビット幅」を持っているという意味です。

http://googleusercontent.com/image_content/158



---

### 3. `@` と `posedge` の意味
*   **`@`**: 
    「〜のとき」という**感度リスト**を表す記号です。`always @(...)` で「カッコの中の条件が満たされた時だけ、中身を実行せよ」という意味になります。
*   **`posedge`**: 
    **Positive Edge（立ち上がり縁）**の略です。信号が `0` から `1` に変化した瞬間のことを指します。
    つまり `always @(posedge CLK)` は、「時計の針（クロック）がカチッと動いた瞬間だけ、計算しなさい」という命令になります。

---

### 4. `26'h0` や `3'd4` の読み方（数値表現）
ここが一番勘違いしやすいポイントです。これらは変数ではなく、**定数の書き方**です。

**書式： `[ビット幅]'[基数][数値]`**

*   **`26'h0`**: 「26ビット幅の、16進数(h)で、0」
*   **`1'h1`**: 「1ビット幅の、16進数(h)で、1」
*   **`3'd4`**: 「3ビット幅の、10進数(d)で、4（2進数だと 100）」
*   **`3'b101`**: 「3ビット幅の、2進数(b)で、5（101）」

`h` は Hexadecimal（16進数）、`d` は Decimal（10進数）の頭文字です。

---

### 5. `always` はループか？
プログラミングの `while(1)` のようなループに見えますが、ハードウェア的には**「常に存在する回路」**という意味です。
FPGAの中に「クロックが来るたびに＋1する回路」が物理的に作られ、電源が入っている限りずっと動き続けるイメージです。

---

### 6. `<= (非ブロッキング代入)`
*   **意味**: 
    おっしゃる通り、数学やC言語では「以下」という比較演算子ですが、Verilogの `always @(posedge ...)` の中では**「代入（右の値を左に入れる）」**を意味します。
*   **なぜ `=` を使わないのか？**: 
    FPGA内部では、数千・数万のレジスタが**「クロックの瞬間に一斉に」**動きます。
    `=` を使うと上から順に処理されてしまいますが、`<=` を使うことで「全ての計算を同時に行い、次のクロックの瞬間に一斉に値を更新する」という同時並行の動きを表現できます。



---

### まとめ
このコードを日本語で翻訳するとこうなります。
> 「CLKが 0 から 1 になった瞬間に、もしRSTが 1 なら `cnt26` を 0 にしなさい。そうでなければ、`cnt26` に `1` を足したものを次の値として予約しなさい」

少しずつ、この「時間の概念（クロック）」がある書き方に慣れていくのがFPGA上達の近道です！

## XDC explanation by Gemini

Verilogのコードが「設計図」なら、この **XDCファイル（Xilinx Design Constraints）** は、その設計図を現実のチップのどのピンに繋ぐかを指定する「**配線指示書**」です。

Cora Z7Sというボード上の物理的なピンと、プログラム内の変数名を結びつける役割を持っています。一行ずつ解説しますね。

---

### 1. クロックの設定（物理ピンと電圧）
```tcl
set_property PACKAGE_PIN K17       [get_ports { CLK }]
set_property IOSTANDARD LVCMOS33    [get_ports { CLK }]
```
*   **`PACKAGE_PIN K17`**: ボード上のZynqチップにある「K17」という名前のピンに、プログラムの `CLK` を繋ぎなさいという意味です。
*   **`IOSTANDARD LVCMOS33`**: 電圧の規格指定です。「3.3Vのデジタル信号として扱います」という宣言です。

### 2. クロックのタイミング定義
```tcl
create_clock -add -name sys_clk_pin -period 8.00 -waveform {0 4} [get_ports { CLK }]
```
*   **`-period 8.00`**: クロックの周期を **8.00ナノ秒** に設定しています。
    *   計算すると $1 / 8ns = 125MHz$ となり、このボードの基本クロックが125MHzであることをツールに教えています。
*   **`-waveform {0 4}`**: 8ナノ秒のうち、0〜4nsが「高(1)」、4〜8nsが「低(0)」という波形（デューティ比50%）であることを示しています。



### 3. リセットボタンの設定
```tcl
set_property -dict { PACKAGE_PIN Y16    IOSTANDARD LVCMOS33} [get_ports { RST }];  #BTN[3]
```
*   **`PACKAGE_PIN Y16`**: プログラムの `RST` を、ボード上のボタン（BTN3）に繋いでいます。
*   **`-dict { ... }`**: さきほどの2行分（ピン番号と電圧規格）をまとめて書く便利な書き方です。

### 4. RGB LEDの設定（注意点あり！）
```tcl
set_property -dict { PACKAGE_PIN V16    IOSTANDARD LVCMOS33} [get_ports { LED_RGB[2] }];  #RED
set_property -dict { PACKAGE_PIN V16    IOSTANDARD LVCMOS33} [get_ports { LED_RGB[1] }];  #Green
set_property -dict { PACKAGE_PIN V16    IOSTANDARD LVCMOS33} [get_ports { LED_RGB[0] }];  #Blue
```
*   **`LED_RGB[2]`〜`[0]`**: Verilogで書いた3ビットの出力信号を、それぞれ物理ピンに割り当てています。
*   **⚠️ おや？**: このコード、全てのピン番号が `V16` になっていますね。これだと赤・緑・青が全部同じピンにぶつかってしまいます。
    *   実際のCora Z7の回路図では、例えば赤が `L15`、緑が `G17`、青が `N15` のように別々のピンが割り振られているはずです。お手元のマニュアルやサンプルを確認してみてください。

---

### 用語の補足

*   **`set_property`**: 「設定（プロパティ）を固定する」というコマンド。
*   **`get_ports`**: プログラム（Verilog）側で定義した `input` や `output` の名前を探してくるコマンド。
*   **`#`**: コメントです。人間用のメモで、ツールは無視します。

### 少し気になるポイント（修正のヒント）
このXDCのままだと、Vivadoで「Implementation（配置配線）」をする時に**「同じピン（V16）に複数の信号を割り当てようとしてるよ！」というエラー**が出るかもしれません。
もしエラーが出たら、LEDのピン番号をボードの仕様に合わせて書き換えてみてくださいね。

## Trouble shootings

### Vivado auto connect failure

ハードウェア的には正しく設定されている（ジャンパピンがUSB給電・JTAGモード、電源LEDが点灯している）ようですので、原因は**Ubuntu OS側のUSBデバイス認識権限（udevルール）**にある可能性が非常に高いです。

Linux版のVivadoでは、インストール後に「ドライバのインストール（設定）」を手動で行わないと、JTAGケーブル（USBケーブル）にアクセスする権限が一般ユーザーに与えられません。

以下の手順を順に試してみてください。

---

### 1. ケーブルドライバのインストール（最優先）
ターミナルを開き、以下のコマンドを順番に実行してください。

```bash
# ドライバ設定スクリプトがあるディレクトリに移動（2023.2の場合）
cd /tools/Xilinx/Vivado/2023.2/data/xicom/cable_drivers/lin64/install_script/install_drivers/

# 管理者権限でスクリプトを実行
sudo ./install_drivers
```
実行が完了したら、**一度USBケーブルを抜き差し**してください。

### 2. UbuntuがUSBデバイス自体を認識しているか確認
ターミナルで以下のコマンドを打ち、デバイスが見えているか確認します。
```bash
lsusb
```
リストの中に `Future Technology Devices International, Ltd FT2232C/D/H Dual UART/FIFO IC`（または Digilent 関連の名称）があれば、パソコンとの物理的な接続は成功しています。これが表示されない場合は、ケーブルをデータ転送用（充電専用ではないもの）に変えてみてください。

### 3. `hw_server` の手動確認
VivadoのAuto Connectが失敗する場合、ターミナルで直接サーバーを立ててエラーメッセージを見るのも手です。
```bash
# パスが通っている場合
hw_server
```
ここで `Access denied` や `Permission denied` が出る場合は、やはりドライバ（udevルール）の設定不足です。

### 4. ユーザーを `dialout` グループに追加（念のため）
USB経由の通信（シリアルポート等）を行うための権限をユーザーに付与します。
```bash
sudo usermod -a -G dialout $USER
```
※これを実行した後は、一度ログアウトして再ログイン（または再起動）しないと反映されません。

---

### 追加のチェックポイント：
*   **ケーブルの品質**: Zynqボードは意外と電力を食います。細いケーブルだと給電不足でJTAG通信が安定しないことがあるので、可能なら太めのしっかりしたデータ転送用ケーブルを使ってください。
*   **仮想マシンの場合**: もしVMwareやVirtualBox上のUbuntuを使っている場合は、ホストOS（Windows等）からゲストOS（Ubuntu）へUSBデバイスを「接続（パススルー）」する設定が必要です。

まずは **手順1の `install_drivers`** を試して、Vivadoを再起動してみてください。これで解決することがほとんどです！
